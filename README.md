# سندك الطبي — الموقع

موقع ساكن (HTML/CSS/JS بلا بناء) يعرض تفاصيل المرافق الصحية وجدولاتها من نفس
قاعدة بيانات تطبيق «سندك الطبي»، ويتيح الحجز والدخول ومشاركة المواعيد
والمخيمات الطبية عبر نفس دوال الحافة (Supabase Edge Functions) التي يستعملها
التطبيق — لا نسخة بيانات ثانية. مستضاف على Render.com كـ Static Site على
`https://sndk-codey.onrender.com`.

## الروابط

- `/facility/<uuid>` — صفحة مرفق (الرابط الذي يُشارَك من التطبيق).
- `/appointment/<schedule_id>` — تفاصيل موعد فردي، حجز مباشر، وتوثيق رقم استباقي. نفس الرابط الذي ينتجه زرّ المشاركة في تطبيق فلاتر (`DeepLinkType.appointment`).
- `/camps` — قائمة المخيمات الطبية.
- `/camp/<uuid>` — تفاصيل مخيم وتسجيل فيه.
- `/` — صفحة رئيسية تعريفية.

## كيف يعمل التوجيه

الاستضافة ساكنة بحتة — لا خادم يعيد كتابة `/facility/<uuid>` إلى ملف حقيقي.
`404.html` يلتقط أي مسار غير معروف (`js/404-redirect.js`)، ويحوّله إلى
الصفحة الحقيقية بمعاملات استعلام (مثلاً `facility.html?id=<uuid>&pretty=1`)؛
تلك الصفحة تُعيد المسار الجميل إلى شريط العنوان بـ`history.replaceState` بعد
أن تقرأ المعرّفات — فيرى الزائر الرابط الجميل كما هو، بقفزة واحدة غير محسوسة.

`js/routing.js` يحمل `sndkBasePath()` — فارغة دائماً على Render (يُخدَّم من
الجذر)، ولا تُستعمَل إلا لو نُشر الموقع يوماً تحت مسارٍ فرعي (كصفحات GitHub
الافتراضية `/sndk.app/`).

## سياسة الدفع

الحجز الذي يتطلّب رسماً **لا يُقبل بلا دفع من أي واجهة** — لا لأن الموقع يمنعه، بل
لأن القاعدة نفسها تفرضه بصرف النظر عن العميل: `book_appointment()` يُنشئ حجزاً
كهذا بحالة `pending` دائماً (بلا `confirmed_at`)، و`confirm_appointment()`
يرفض التأكيد صراحةً (`SNDC8`) ما لم توجد نيّة دفع بحالة `paid`/`partially_refunded`
مرتبطة بالحجز، والتحويل الفعلي إلى `confirmed` لا يمرّ إلا عبر
`payment_apply_gateway_result()` (ويبهوك البوّابة أو مطابقة `payment-status`) —
لا مسار عميل آخر يصل إليه. هذا يسري على تطبيق فلاتر والموقع معاً لأن كليهما
يستدعي نفس دوال الحافة (`create-appointment`, `create-payment`, `payment-status`)
التي تستدعي نفس دوال القاعدة. `js/payment.js` + قسم الدفع في `js/booking.js`
هما مرآة الموقع لـ`payment_service.dart` + `booking_payment_sheet.dart` في
التطبيق — نفس الأفعال، ونفس تصنيف الحالة (`isInFlight`/`isSettled`)، ونفس
القاعدة: لا يُعتدّ بعودة المستخدم من صفحة البوّابة، الحالة تُقرأ من
`payment-status` وحده.

## الحماية

- `Content-Security-Policy` صارمة على كل صفحة: `script-src 'self'` بلا أي
  استثناء — صفر سكربت داخلي أو خاصّية `onclick=`/`onerror=` في كامل الموقع؛
  كل الربط بالأحداث عبر `addEventListener` في ملفات `.js` خارجية.
- كل نصّ مصدره الخادم (اسم مرفق، اسم طبيب، رسالة خطأ، ملاحظة مريض…) يمرّ عبر
  `esc()` (`js/common.js`) قبل أن يدخل `innerHTML`، وكل قيمة تدخل خاصّية HTML
  (مثل `value="..."`) تمرّ من نفس الدالة.
- أيقونات الاحتياط عند فشل تحميل صورة عبر مفتاحٍ اسمي (`data-fallback-type`)
  لا ترميز HTML خام داخل خاصّية.

## الاتصال بـ Supabase

`js/config.js` يحمل رابط المشروع والمفتاح العام (publishable/anon). هذا
المفتاح **ليس سرّاً** — هو نفسه المضمَّن في حزمة تطبيق أندرويد، فأي محاولة
فكّ للحزمة تستخرجه أصلاً. الحدود الحقيقية (من يحجز، من يوثَّق، حدود المعدّل)
مفروضة داخل دوال الحافة نفسها لا في سرّية هذا المفتاح — وهو نفس النموذج الذي
يعمل به التطبيق المحمول.

## البنية

```
index.html            الصفحة الرئيسية التعريفية
facility.html          صفحة المرفق
appointment.html       تفاصيل موعد فردي + حجز + توثيق هاتف استباقي
camps.html             قائمة المخيمات الطبية
camp.html              تفاصيل مخيم + تسجيل
404.html               حيلة التوجيه للمسارات الجميلة
css/app.css             نظام تصميم مطابق لـ lib/utils/theme.dart في التطبيق
js/routing.js           sndkBasePath() المشتركة
js/common.js            esc/cleanPhone/أيقونات الاحتياط — مشتركة بين كل الصفحات
js/config.js            رابط Supabase ومفتاحه العام
js/api.js               غلاف نداء دوال الحافة (نظير ApiService)
js/auth.js              الجلسة: دخول/تسجيل/تجديد توكن (نظير AuthService)
js/auth-ui.js           واجهة مودال الدخول والتسجيل
js/booking.js           تدفّق الحجز الكامل: تقويم → تأكيد → توثيق هاتف → إرسال → دفع إن استوجب
js/payment.js            نيّة الدفع واستقصاء نتيجتها (create-payment / payment-status)
js/facility.js          منطق صفحة المرفق
js/appointment.js       منطق صفحة الموعد الفردي
js/camps.js             منطق قائمة المخيمات
js/camp.js              منطق صفحة المخيم والتسجيل
js/404-redirect.js      إعادة التوجيه من 404.html وحده
```

## النشر (Render.com)

الخدمة من نوع **Static Site** (لا Web Service — لا حاجة لأمر بناء أو تشغيل):

1. New → Static Site → اختر هذا الريبو والفرع `main`.
2. Build Command: فارغ. Publish Directory: `.`
3. Root Directory: اتركه فارغاً (هذا الحقل لمجلّد فرعي في monorepo، لا للملف الرئيسي).
4. لا نطاق مخصّص حالياً — الرابط المباشر `https://sndk-codey.onrender.com` كافٍ.
